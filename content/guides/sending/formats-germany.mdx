## Pick the document format

Send **Peppol BIS 3 UBL** unless the recipient asks for XRechnung. When a
recipient is only registered for XRechnung, Recommand picks it automatically;
to ask for it explicitly, name its document type on the send request:

| What you send                        | `doctypeId`                                                                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Invoice or credit note (default)     | not needed, defaults to Peppol BIS 3 UBL                                                                                                          |
| XRechnung 3.0 UBL invoice            | `urn:oasis:names:specification:ubl:schema:xsd:Invoice-2::Invoice##urn:cen.eu:en16931:2017#compliant#urn:xeinkauf.de:kosit:xrechnung_3.0::2.1`       |
| XRechnung 3.0 UBL credit note        | `urn:oasis:names:specification:ubl:schema:xsd:CreditNote-2::CreditNote##urn:cen.eu:en16931:2017#compliant#urn:xeinkauf.de:kosit:xrechnung_3.0::2.1` |
| XRechnung 3.0 CII invoice or credit note | `urn:un:unece:uncefact:data:standard:CrossIndustryInvoice:100::CrossIndustryInvoice##urn:cen.eu:en16931:2017#compliant#urn:xeinkauf.de:kosit:xrechnung_3.0::D16B` |

The document you post is the same for every format. XRechnung does require a few
fields that are optional elsewhere, and a send that misses one is refused with
the full list before anything is transmitted:

- `buyerReference` (BT-10), unless it is filled in from a Leitweg-ID (see below)
- `paymentMeans`, at least one payment instruction
- the seller's `phone` and `email`, and the seller's and buyer's city and postal code
- for a CII credit note, `paymentTerms`

Peppol BIS 3 applies the same payment instruction and seller contact rules to
every German seller, so fill them in whichever format you send.

Raw XRechnung XML can be sent as it is with `documentType: "xml"`: the document
type and process are read from the document, for UBL and CII alike. XRechnung
3.0 extension documents and earlier XRechnung versions are sent under the
identifier the document declares, but are not read.

### Invoicing a public authority

Address the authority by its Leitweg-ID, as `0204:` followed by the Leitweg-ID.
German public authorities require XRechnung, so a document to a Leitweg-ID is
written as XRechnung by default, also when the authority is registered for
Peppol BIS 3 as well. The XRechnung fields listed above are therefore required.
The same Leitweg-ID has to be the invoice's buyer reference (BT-10), so leave
`buyerReference` out and Recommand fills it in. A different `buyerReference` is
refused, because the authority would reject the invoice; put order numbers in
`purchaseOrderReference` instead.

```json title="invoice to a public authority"
{
  "recipient": "0204:991-33333TEST-33",
  "documentType": "invoice",
  "document": {
    "invoiceNumber": "RE-2026-001",
    "purchaseOrderReference": "4500012345",
    "buyer": { "name": "Bundesamt für Beispiele", "street": "Amtsweg 2", "city": "Bonn", "postalZone": "53113", "country": "DE" },
    "paymentMeans": [{ "paymentMethod": "credit_transfer", "iban": "DE89370400440532013000", "reference": "RE-2026-001" }],
    "lines": [{ "name": "Beratung", "quantity": "1", "netPriceAmount": "100.00", "vat": { "category": "S", "percentage": "19.00" } }]
  }
}
```

<Callout type="info" title="Before a first invoice to a federal authority">
  Each authority and portal sets its own acceptance terms. Confirm the format
  the authority accepts, and check that the recipient is reachable with the
  [verify document support endpoint](/reference/recipients/verify-document-support)
  before the first send.
</Callout>

## Buyers that are not on Peppol

Every German business has to be able to receive structured e-invoices, but not
every one is on Peppol. The law does not prescribe a channel: an XRechnung or
Peppol BIS XML delivered by email is a valid e-invoice, a PDF is not. Two ways
to reach every buyer with a structured document:

**Peppol first, email as fallback (recommended).** Address the buyer by its VAT
number, `9930:` followed by the number, and add `email.to`. When the buyer is
on Peppol, the invoice goes over Peppol. When the Peppol network says the
address is not registered, no transmission is attempted and the invoice is
emailed straight away, with the XML attached. The Peppol delivery then reports
`recipient_not_found`.

```javascript title="Peppol first, email as fallback"
{
  recipient: "9930:DE123456788",
  documentType: "invoice",
  document: {
    // ... your invoice data, with the buyer's vatNumber
  },
  email: { to: ["rechnung@kunde.example"] },
}
```

`email.when` defaults to `on_peppol_failure`, so the email only goes out when
Peppol delivery fails. A Peppol lookup that fails for another reason, such as a
directory that does not answer, does not count as not registered: the
transmission is attempted as usual, and the email only goes out if that
attempt fails.

**Email only.** When you know the buyer is not on Peppol, set `recipient` to
`null` and name the format with `doctypeId`. The invoice is written in that
format, validated as for a Peppol send, and attached to the email as XML.

```javascript title="XRechnung by email"
{
  recipient: null,
  documentType: "invoice",
  doctypeId:
    "urn:oasis:names:specification:ubl:schema:xsd:Invoice-2::Invoice##urn:cen.eu:en16931:2017#compliant#urn:xeinkauf.de:kosit:xrechnung_3.0::2.1",
  document: {
    // ... your invoice data
  },
  email: { to: ["rechnung@kunde.example"] },
}
```

The invoice names the buyer's VAT number as its electronic address (BT-49), or
the first address in `email.to` when the buyer has no VAT or enterprise
number. XRechnung accepts the email address; Peppol BIS 3 does not, and needs
the buyer's VAT number. Without `doctypeId`, an email-only send carries a PDF
and no XML. See [email delivery](/docs/email-delivery-and-notifications#structured-documents-by-email)
for the details.
